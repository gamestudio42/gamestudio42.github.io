03 / SO ENTWICKELN WIR

Zum Spielen gemacht.
Offen für Möglichkeiten.

Wir bauen Welten, in denen Entscheidungen Spuren hinterlassen: Ein Kanal belebt ein Viertel, eine Versorgungsroute hält einen Trupp am Leben, ein Block wird zum Schutzraum. Bei Game Studio 42 beginnt Spielen mit Simulation. Viele Spiele starten sofort im Browser; einige erscheinen auch als Desktop-Apps. Jedes System lässt sich verstehen und verändern.

Gemeinsam und offen entwickelt.

Game Studio 42 verbindet unabhängige Entwicklung mit offener Zusammenarbeit. Hinter jedem Spiel stehen Menschen, die Code schreiben, Welten gestalten und sich um Details kümmern. Spiele mit, teile eine Idee oder gestalte die nächste Version mit.

Finde uns auf GitHub
42ALWAYS
EXPLORING.
  1. 01

    Weniger Hürden. Mehr Spiel.

    Öffne einen Tab und spiele mit einem Klick — oder installiere den Desktop-Build, wo verfügbar. Der Code bleibt in beiden Fällen offen.

  2. 02

    Entdecke die Regeln.

    Lies den Code, ändere eine Mechanik oder gib einem Spiel eine völlig neue Richtung.

  3. 03

    Offen entwickelt.

    Verfolge die Entwicklung, melde einen Fehler oder steuere eine Änderung bei. Jedes Repository ist ein Anfang.

04 / MIT DER COMMUNITY WACHSEN

Dein Projekt kann mit Game Studio 42 wachsen.

Bring dein Open-Source-Spiel oder deine Technologie für Spiele mit: Engines, Frameworks, Bibliotheken, SDKs, Werkzeuge und KI-Agenten. Jede Engine. Jede Plattform.

01 /

Gemeinsame Wartung

Bleibe als Maintainer beteiligt und entwickle dein Projekt gemeinsam mit anderen Mitwirkenden weiter.

02 /

Übernahme durch die Community

Schlage ein neues Kapitel für dein Projekt vor und finde Maintainer, die es weiterführen.

Ein Repository in der Organisation und gemeinsame Zusammenarbeit nach der Freigabe. Die Aufnahme in den Katalog wird separat geprüft.

Projekt vorschlagenSo funktioniert esOpen Source

Klare Standards, Raum für jedes Projekt.

Wir bevorzugen AGPL-3.0-or-later für Spiele und Multiplayer-Server sowie Apache-2.0 für wiederverwendbare Technologie. MIT, BSD, GPL und andere Open-Source-Lizenzen kommen ebenfalls nach Prüfung infrage. Ausnahmen werden dokumentiert; die Aufnahme erfordert keine automatische Lizenzänderung. Bestehende Projekte behalten ihre Lizenzen.

Lizenzleitfaden lesen

Öffentliche Vorschläge auf GitHub · Auf Englisch oder Portugiesisch

Projekte in Entwicklung sind willkommen, wenn bereits Code zur Prüfung vorliegt. Die Aufnahme erfordert eine Prüfung und einen bestätigten Maintainer; Übernahmevorschläge können auf Freiwillige warten. Urheberschaft, Credits und Historie bleiben erhalten.
